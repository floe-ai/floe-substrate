# F73/F74 — reliable history pages and fixed Context validation

The preceding goal turn made progress: 0.1.72 installed discoverable instruction
bindings, a real review returned through its stored Edge, and the browser opened
named evidence. The label repair also exposed a fixed Context configuration that
publication accepted but execution could not use. That configuration was corrected

## Observed need and classification

F73: a bounded history read must return a usable page and continuation reference.
The earlier tool cut its serialized JSON at 16,000 characters, sometimes removing
part of an Event and the cursor. A live repair tried an Event ID and timestamp as
replacement cursors; both failed. This is a Bridge representation correction over
the existing Context history read, not a new history source.

F74: a saved fixed execution Context must satisfy the same Workspace, Scope,
lifecycle and content constraints already enforced when the node activates.
The label repair selected the outside operator conversation for a Scope placement;
validation and publication accepted it. This is shared validation of an existing
constraint, not permission to widen Context boundaries or add a primitive.

## Changes

History pages now contain whole contribution previews and the exact Bus-issued
cursor. If a page exceeds the response budget, the Bridge requests a smaller
prefix from the same position and returns its matching cursor. One oversized
Event retains its identity and explicitly identifies omitted payload fields.
Existing text preview truncation is now labelled. No canonical content changes,
cross-Context prompt injection, cursor synthesis or recurring polling is added.
Telemetry records response size, actual Event count, internal page-read count and
omitted-field count.

The Bus uses the same fixed Context availability check during validation,
publication, rollback and node activation. Invalid drafts remain inspectable and
return a diagnostic. Publication and rollback refuse before changing the published
head. Activation retains its check because a Context can become unavailable after
publication. The discovered fixed Context field explains the existing constraint.
